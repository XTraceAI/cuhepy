# Deterministic support bounds for joint BGV packing

This E15 experiment starts from the checkpoint in
[PR #14](https://github.com/XTraceAI/cuhepy/pull/14), commit `3c0a547`, on the
separate branch `experiment/bgv-verification-packing`. The public C++/CUDA
arithmetic, keys, ring, ciphertext modulus and packet formats are unchanged.
The experiment substitutes a tighter deterministic bound for the existing joint
trace/packing circuit and measures what this permits in the precision planner.
It does not introduce a new packing primitive or establish novelty.

## Bound and derivation

Work in the integer ring `R = Z[X]/(X^N+1)`, with N a power of two. Let D be
the padded dimension, a power of two with `1 <= D <= N/2`, and
`sigma(f) = f(X^(1+2N/D))`. The subgroup generated by sigma has order D.
Its trace obeys the exact integer identity

```
Trace_D(f) = sum_(a=0..D-1) sigma^a(f)
           = D * sum_(D divides k) f[k] X^k.
```

The joint butterfly maps the shifted, relinearized input phases `f_i` to
`sum_i X^i Trace_D(f_i)`, before accounting for errors injected by its
automorphism key switches. Input i occupies precisely the coefficient positions
congruent to i modulo D. These supports are disjoint, so for `||f_i||inf <= B_i`
the input contribution has norm at most `D * max_i B_i`. Taking a triangle
bound separately at each butterfly node loses this cancellation and instead
charges `D * sum_i B_i`.

At level j (starting at zero), let `m = D / 2^(j+1)`. An arbitrary switch error
polynomial at node i is acted on by the remaining suffix butterfly. That suffix
is `X^i Trace_m`, using the subgroup generated by `sigma^(2^(j+1))`. Its support
is congruent to i modulo m. At a fixed level, the active nodes again have
disjoint supports. If **each** error polynomial has norm at most S, that whole
level contributes at most `m*S`, including correlated errors.

Summing the levels gives the final whole-polynomial bound

```
B_final <= D * max_i B_i + (D-1)*S
B_i     <= N * B_query * B_index_i + S_relinearize
```

Here both switch types use the existing deterministic gadget bound
`S = t*eta*N*(2^digit_bits-1)*digit_count`. The bound includes relinearization,
all automorphism switches and unused output coefficients. Missing tail inputs
are zero; a partial group cannot increase the bound. D=1 has no automorphism
switches and reduces to its single input bound. This derivation assumes no
independence, Gaussian error approximation or observed private noise.

For K input tiles with a uniform bound B, the previous input term is `D*K*B`.
At K=D its switch term is `(D^2-1)*S/3`; the new one is `(D-1)*S`. Bounds on
different levels may still be added because their errors need not cancel.

These are integer lifts of phases, congruent to the evaluated ciphertext phases
modulo Q. No intermediate centered decoding is performed. The final bound must
be strictly below Q/2. The existing terminal reduction then still requires

```
B_terminal = ceil(P * B_final / Q) + ceil((N+1)*t/2) < P/2.
```

The query quantization error is included in `B_query`. Response c0 quantization
adds its existing deterministic error **after** terminal reduction; that sum
must also stay below P/2. We do not change either codec or weaken those checks.
The terminal rounding term can dominate, so a much tighter pre-terminal bound
does not imply a proportional decrease in response bytes.

## Implementation and checks

- [`support_bounds_bgv.py`](../../experiments/bfv_search_lab/support_bounds_bgv.py)
  defines `cuhepy-lab-bgv-joint-support-bound-v1` and an explicit
  `SupportBoundServer`. It inherits the existing native evaluator and changes
  only public bound calculation. It refuses the separate per-tile trace path,
  whose key-switch errors are injected in a different schedule.
- [`test_support_bounds_bgv.py`](../../experiments/bfv_search_lab/test_support_bounds_bgv.py)
  uses independent sparse symbolic polynomials. Every input/error coefficient
  is a separate indeterminate; signed aliases are combined exactly. It verifies
  every coefficient, level, supported tiny-ring dimension and tail shape,
  plus arbitrary unequal input bounds and worst-case correlated error signs.
  Encrypted CPU cases check complete ciphertext identity and exact distances.
- [`test_cuda_support_bounds_bgv.py`](../../experiments/bfv_search_lab/test_cuda_support_bounds_bgv.py)
  compares independent CPU/CUDA complete packets, all old admissible precision
  choices, and exact encrypted results at the new planner frontier. It covers
  public-key and owner-encrypted indexes, partial groups and multiple responses.
- [`bgv_support_bounds.py`](../../benchmarks/bgv_support_bounds.py) measures
  paired policies with shared keys/index/fresh encryption, shuffled request
  order, one excluded warmup, and every distance and stable top-three checked.
  Setup, planning and duplicate fixture evaluation are recorded separately.

The original server, authentication policy and production package are untouched.
Bounds remain trusted owner metadata, **not** evidence that a server evaluated
correctly. The local/TCP fixtures compare complete known ciphertext bytes before
private processing. That duplicate evaluation is excluded from request timings;
these measurements do not provide an efficient authenticated GPU service.
Any future attested/proved protocol must bind and review the new bound policy.

The mathematical argument and regression checks address correctness. They do
not certify lattice hardness, private side channels or malicious-server safety.
Independent review remains necessary. Tiny rings are algebra tests only.

## Measured precision and complete request cost

The [8,192-vector artifact](../../benchmarks/results/bgv_support_bounds_8192.json)
and [32,768-vector artifact](../../benchmarks/results/bgv_support_bounds_32768.json)
were measured at source commit `8b47f31` on the RTX 3080 10 GiB, Ryzen 7 5800X,
with the checkpoint's native binaries. Both use N=16,384, dimension D=512,
Q120, t=1,031 and eta=21. Q120 is a modulus size, not a security level.
Each pair shares its keys, index and fresh query ciphertext. Both policies use
the indexed NTT, CUDA level 4, persistent workspace, GPU terminal conversion,
native codecs and packed owner finishing. The planner minimizes query plus
response **bytes**, without assuming that this also minimizes latency.

All sizes below are exact framed application bytes. TCP adds eight bytes for
the two length prefixes; TLS, IP and authentication are excluded. The old and
new policies use the **same response size** in these selected plans.

| Vectors | Index encryption | Old query | New query | Response | Old total | New total | Total reduction |
|---:|---|---:|---:|---:|---:|---:|---:|
| 8,192 | Public-key | 149,612 | 133,228 | 79,971 | 229,583 | 213,199 | 7.14% |
| 8,192 | Owner | 118,892 | 102,508 | 79,971 | 198,863 | 182,479 | 8.24% |
| 32,768 | Public-key | 153,708 | 135,276 | 155,754 | 309,462 | 291,030 | 5.96% |
| 32,768 | Owner | 122,988 | 104,556 | 155,754 | 278,742 | 260,310 | 6.61% |

At 8,192 vectors, query drop increases by eight bits (58→66 for public-key
index, 73→81 for owner index). At 32,768, it increases by nine bits (56→65 and
71→80). Terminal precision stays 25 bits; response c0 drop stays 22/23 bits
respectively. That saves 16/18 KiB of upload. The smaller uniform bound stops
charging for unrelated tiles, but cannot remove terminal rounding's floor.

Owner index encryption is a separate ingestion option with a smaller fresh
phase bound. It does not make an existing public-key index smaller automatically;
switching modes requires rebuilding the encrypted index. Within a row the index
and keys are identical under both policies. Full index coefficient bytes remain
125,829,120 and 503,316,480, respectively; serialized keys were not remeasured.

The following are median **complete** milliseconds: query encoding/encryption,
query codec, public server expansion/evaluation/codec, response handling and
private distance/top-three finishing. Local runs have ten fresh paired trials;
each paced TCP link has five, with one excluded warmup. Median components need
not sum to the median total. These samples support a small experiment, not a
p95/tail claim or a hardware-general performance claim.

| Vectors | Index | Local old → new | 10 Mbps up / 100 Mbps down, 40 ms RTT | 10 Mbps both ways, 40 ms RTT |
|---:|---|---:|---:|---:|
| 8,192 | Public-key | 48.88 → 48.86 | 216.79 → 203.82 | 274.29 → 261.47 |
| 8,192 | Owner | 48.06 → 48.37 | 192.27 → 178.91 | 249.51 → 236.27 |
| 32,768 | Public-key | 89.97 → 88.74 | 266.46 → 249.98 | 378.66 → 364.03 |
| 32,768 | Owner | 90.35 → 89.58 | 242.46 → 227.81 | 353.76 → 340.13 |

The compute circuit is unchanged and these local fluctuations do not establish
a compute speedup. All four local paired-difference ranges cross zero. All paced
link pairs improved: the public-index median paired change is -13.07/-16.12 ms
on the asymmetric link and -12.68/-14.76 ms on the symmetric link, at 8,192/32,768
vectors. Saving 16/18 KiB at a 10 Mbps upload rate predicts 13.11/14.75 ms of
transfer reduction alone. These are paced localhost fixtures, not an AWS/WAN
deployment measurement.

Excluded duplicate expected-response evaluation has a median cost around
30.5–31.5 ms at 8,192 and 66.0–67.5 ms at 32,768, depending on policy/index mode.
Its complete pinned bytes are checked before private processing. This work is
necessary to the current benchmark fixture, and **must not** be represented as
free efficient GPU authentication. Key generation/evaluation-key setup took
roughly 0.10/2.94 s. Public index encryption took 33.00/135.89 s and owner index
encryption/expansion took 4.12/16.53 s at the two sizes. Per-policy server/index
preparation and workspace allocation are also recorded separately in the JSON.

Every measured distance and stable top-three result was correct. At the same
precision, both policies also produced identical complete ciphertext packets.
The 22 focused symbolic/encrypted CPU/CUDA tests passed before measurement.
No native arithmetic changes were made for this experiment.

The complete package/BFV-example/research regression on 2026-09-27, with CUDA
required and the independent SEAL oracle enabled, passed **927 tests**, with
one live AWS Nitro integration test skipped and the existing fork deprecation
warning, in 208.38 s. This includes the 19 new verification-oracle tests.
Package Ruff, full Ruff on the new Python files, package mypy (34 source files)
and whitespace checks passed. Sanitizers and real enclave deployment were not
rerun for this Python/model-only change.

This is a positive E15 result: a deterministic bound improvement reduces upload
without changing the ring or evaluator. The next performance experiment can
combine it with E16 radix packing, accounting for the larger plaintext modulus
and terminal precision rather than assuming that fewer tiles halve wire bytes.
The [verification inventory](bgv-verification-relations.md) separately begins
E13/E14; the GPU authentication gap remains open.

## Reproduction

Build the existing BGV native and CUDA modules as documented in the
[lab README](../../experiments/bfv_search_lab/README.md). No native rebuild is
needed if the checkpoint's binaries are already present. Run measurements
without simultaneous builds, tests or other GPU work:

```bash
CUHEPY_REQUIRE_BGV_CUDA=1 .venv/bin/python -m pytest \
  experiments/bfv_search_lab/test_support_bounds_bgv.py \
  experiments/bfv_search_lab/test_cuda_support_bounds_bgv.py -q
.venv/bin/python benchmarks/bgv_support_bounds.py --num-vectors 8192 \
  --json-out benchmarks/results/bgv_support_bounds_8192.json
.venv/bin/python benchmarks/bgv_support_bounds.py --num-vectors 32768 \
  --json-out benchmarks/results/bgv_support_bounds_32768.json
```

The artifact records every timed sample, public bounds, byte counts and
source/binary hashes. It does not save ciphertexts, cryptographic seeds, keys
or plaintext embeddings. Deterministic seeds identify synthetic plaintext
generation and variant ordering only.
