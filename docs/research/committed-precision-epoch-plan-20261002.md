# Q19/E93: committed precision families before a fresh target-key epoch

2026-10-02. **Proposed, not implemented or selected.** This is the R6 return
after [E92](partial-packed-switch-screen.md), not a restarted zero-mask recipe.
The candidate is a complete ordering/assurance/resource trade, not a claim that
concentration bounds, fresh keys or approximate switching are new mathematics.

## First prerequisite: a discriminating source budget

All original-q E92 cards inherit a source bound near q/2. The chosen signed
odd-domain full-LUT route needs a quarter-domain phase margin before rounding,
so those cards already fail at zero omitted levels. Do not tune a mask norm
against an empty budget or treat its failure as a real workload result.

Independently derive the actual source **centered phase** bound and its unit-
converted error, separating messages, key/encryption errors, products and sums.
Do not silently relabel a phase bound as independent Gaussian noise. Compare:

1. Original-q, original public guarantee, explicitly reporting no headroom.
2. A paid changed q/eta context with its bound recomputed and key/index
   regeneration and security premises disclosed. Unchanged-bound inflation
   is a conditional count only, not an assured parameter recommendation.
3. A known full-domain/high-precision method with its actual source margin,
   auxiliary keys and final modulus-switch/PBS obligations.

Return to R6 after this prerequisite. A new source bound or context must have
a justified interface before any parameter/performance conclusion.

## Candidate ordering and restricted lemma

For a finite batch, bind source scores, original encrypted queries, public
mask transformations and allowed layouts/stages **before** sampling a fresh
independent target secret T and its switching-key mask/error randomness.
Both input family and key-generation provenance are owner approved. All
subsequent accepted mask views must be their prescribed public functions;
complete proofs bind the original source and epoch, not just a digest chosen
by the server. Original source S can be arbitrarily dependent on its input:
use deterministic derived-S-squared bounds for that part.

For plus-sign packed switching, its target mask A uses committed source
digits and fresh key **masks**, not key bodies. Before-PBS rounding/remainder
weights w_j(A) can therefore be independent of the freshly sampled T under
the stated ordering. Body rounding remains a worst-case term. Honest key
errors have their own sampler/order and separately paid bound. Do not assume
the full public transcript or posterior T is independent after exposing key
bodies. The proposed security argument uses a failure event over the entire
precommitted family, not conditional independence after every observation.

A first restricted control lemma: for independent mean-zero uniform ternary
T_i and a fixed integer weight vector w, its MGF is bounded by
`exp(lambda^2 * sum(w_i^2) / 2)`. For K preapproved coefficient/stage/view
events, the integer threshold

`ceil_sqrt(2 * max_view_sum_squares * (kappa + ceil_log2(2*K)))`

is a conservative union-bound control at failure target 2^(-kappa). It requires
no Gaussian tail, floating root or independence between different output
events. Actual key distributions need their own valid MGF; fixed-weight,
binary, prefix and reused keys are not interchangeable. This is known
concentration mathematics; no new theorem/protocol is accepted from it alone.

The possible contribution is a **complete source-bound finite-family epoch
rule** permitting useful verified precision selection while handling malicious
postselection and observable feedback. Once all K events are covered, choosing
a subset after seeing the public keys does not add another failure probability.
Future inputs outside the committed family need a new rule/epoch. A seed or
nonce is not a proof of independently sampled masks or correct scores.

## Proof-first finite experiments and strong controls

1. Targeted review: ciphertext drift/quality rerandomization, dependence-noise
   analysis, mean compensation, functional/partial switching, high-precision
   PBS, and malicious/adaptive verified HE. Identify whether they already
   supply the same complete epoch rule. Stop a generic composition claim.
2. Tiny exact probability oracle: entire source/target key laws, public input
   and mask/error coins, precommit versus post-key input choice, whole public
   transcript/posterior distinctions, all approved views and postselection.
   Preserve an explicit adaptive counterexample when ordering is removed.
   No attack on a published scheme is claimed without instantiating it.
3. State the conditional accepted-release lemma before HE privacy hybrids:
   except proof failure plus the **whole-family** noise event, accepted results
   match the original function and ideal feedback. Include epochs, retries,
   key cycles, malicious registration and private work order. Do not infer a
   computational reduction from statistical MGF checks or taint tests.
4. Only after those survive, instantiate an integer public precision-budget
   verifier. It checks original family membership, public squared weights,
   source bound and exact thresholds. Subsequent PBS-generated masks or any
   transformation using key bodies need a fresh dependency analysis.
5. Paid count screen over batch sizes1/8/32/256/4096 and sparse/dense outputs.
   Charge key generation, source-secret preparation, owner CPU/GPU, enrollment
   traffic, extra RTT, proof, retained state, refresh and permitted caches.
   Compare equally sound full deterministic, standard statistical/mean-
   compensated, fresh per-query and known shared-epoch controls. Avoid giving
   a baseline repeated independent per-slot keys. A smaller PBS degree alone
   is not a whole-system gain.

Return to R6 after **each** component. Stop if source headroom remains empty,
the independence/order proof is invalid, the epoch construction is already
known, or complete costs fail the project target. Keep useful company controls.
Q6–Q10 and broad assurance stay conditional. A larger matched BGV/Paillier
evaluation and complete proof/backend adapters remain independent open tasks;
neither supplies originality by itself.
