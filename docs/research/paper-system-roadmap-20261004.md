## 1. Select one scientific question

Build on our homemade native BGV implementation. Ask whether a **specific
placement of representation construction and complete admission** produces a
useful execution that equally optimized protected replay and permitted client
caching do not already provide. Explain the result through paid conversion,
link, retained-state and update costs.

The concrete first comparison is delegated common-Q source construction plus
complete public admission versus deriving those same sources inside the
protected execution boundary. Both produce the identical complete frame.
The proposed contribution is the demonstrated execution/invariant and its
operating conditions. Generic cost-aware selection, sharing query expansion,
feature packing, signatures and a TEE remain credited mechanisms.

The reference construction gets every compatible optimization and the same
information. A smaller internal witness is insufficient: the current exact
aggregate control recomputes the products that prepared replay already computes.
Its useful role is a matched negative control for redundant delegation.

The refreshed matrix includes the adjacent Atlas, Compass and Onyx contracts.
It rules out broad claims of first verifiable search, first private owner
search, first TEE search or first storage/compute co-design. Their adaptation
costs remain unknown; none is numerically defeated by our existing timings.

## 3. The system to assemble

The owner is honest and may retain all plaintext. The cloud host/evaluator is
malicious. The target returns every exact Hamming distance for the current
owner snapshot; top-k uses `(distance, original row ordinal)` and returns the
bound IDs. Approximate graph retrieval, hidden provider data, content fetching
and encrypted top-k-only computation are different contracts.

Keep the components separate so a placement change cannot silently change the
trusted statement or private release:

| Component | Existing implementation / next obligation |
| --- | --- |
| Reference semantics and origin/bounds | `shared_query_bgv.py`, `shared_query_gmp.py`, `shared_query_bounds.py`; preserve the selected owner encoding and actual prime basis. |
| Native execution choices | `_shared_query/shared_query.cpp`, `shared_query_replay.cpp`, `shared_query_aggregate.cpp`, with adjacent Python adapters. Complete public relation, protected replay and exact aggregate produce the same frame. |
| Owner binding and local authority | `authenticated_shared_query.py`, `lifecycle_shared_query.py`; actual nonrollback freshness and attestation remain Q78. |
| Independent static plan/client metadata | `shared_query_certificate.py`, `shared_query_client_context.py`; keep public validation distinct from runtime equality and private capability. |
| Permitted local execution | `authenticated_cache.py` and `_shared_query/cache_popcount.cpp`; grant retention, mutable updates and acquisition/prefetch to the owner. |
| Proof/assurance artifact | `proofs/shared_query/Model.lean`; extend only with stated native/semantic/state obligations, keeping hypotheses explicit. |
| Evaluation and deployment | New separately registered Q77 runner, then the selected Q78 protected deployment and private client handoff. |

All paths above are under `experiments/bfv_search_lab/` unless otherwise
stated. Company Paillier/BFV/BGV/CUDA implementations and fallback examples

## 4. Finite work queue and handoffs

There are **zero preliminary Q74/Q75 gates and zero immediate Q76 native
milestones left**. Three packages remain. Review the ledger after each handoff;
do not add an experiment merely to avoid a negative selection decision.

### Q77: decide the paid execution question

1. Freeze a separate registration before timing or new keys: exact sources,
   two independent key contexts, counts 8,224/16,384/32,768, hardware roles,
   memory/link budgets, arrivals, device lifetimes, updates and initial state.
   State which roles restart in a fresh block and how the two private key
   contexts remain in trusted custody; evidence must not contain private keys.
   Reuse the eligible fixed profile; a failed origin/parameter premise returns
   to registration rather than silently changing the law.
2. Implement one complete dependency graph for each distinct deterministic
   mode and the allowed cache/acquisition/prefetch policies. Charge owner
   setup, provisioning, preparation, producer/admission, every link, private
   finish, selection, 32-row refreshes and actual invalidation. A candidate/
   known-composition alias is not another independent implementation.
3. Use the first process block per key/size for calibration: **6 blocks,
   48 dependent query observations per implementation**. Freeze and hash the
   policy, cost data, admissible choices, trace weights and same-information
   generic selector before proceeding.
4. Run the remaining **12 blocks, 96 dependent held-out observations per
   implementation**. The total cap is 18 blocks/144 observations, with one
   separately excluded warmup per block and separate post-update correctness
   checks. Keep pairing, failures, timeouts, contention, clocks, thermals and
   swap; do not count observations as independent key/corpus setups.
5. Primary metric: mean client-visible completion delay over the frozen
   arrival/device/update trace, ending after authenticated complete distances
   and ordinal top-k. Report cold/warm/update/tail delay, work, links and memory
   separately. Measure actual overlap instead of adding stage medians.
6. Return a pass/stop receipt. A 20% win against the best compatible frozen
   remote policy is only the project gate. Separately show a useful region
   against cache/prefetch and a meaningful strongest-system distinction. An
   exact generic selector with identical choices should match the finite
   optimum; a retrospective per-instance minimum is an oracle, not a policy.

The randomized vFHE adapter is not implemented. Either supply its separately
reviewed commitment/challenge/lifetime argument and paid adapter before a
broad comparison, or explicitly limit numerical claims to the implemented
deterministic class. Unknown prior costs stay unknown. Local prototype timing
does not measure enclave attestation or a secure remote service.

### Q78: deploy the selected useful plan and close its assumptions

Build one selected protected path, rather than every possible platform. For
AWS, verify the actual attestation, measured-code/key binding, owner trust
policy, transport, freshness/revocation and nonrollback state before releasing
private work. A local signer/code digest is insufficient. Verify GPU support
separately if a measured bottleneck selects that route.

Close the layers in the [security feasibility card](native-shared-query-security-feasibility-20261004.md):
concrete primitive/model refinement; honest-origin/no-wrap/terminal semantics;
current at-most-once response authorization; actual samplers/seed expansion,
related-secret evaluation-key assumptions and concrete parameters; private
operations/side channels; and the deployed trusted boundary. Develop a
conditional reduction against an explicit exact-search ideal functionality
with permitted leakage. Do not infer raw ciphertext CCA security from IND-CPA.

Rerun the relevant frozen comparison in the actual deployment and account for
attestation, transport and private handoff. Produce an explicit unresolved-
assumption list and a reviewable assurance package. Until then, keep results
labelled local prototype performance.

### Q79: select and write the paper that the evidence supports

Produce a claim-to-evidence table, precise main statement, strongest-work
comparison, reproducible artifact and paper outline. Seek independent human
originality/security review through the user's authorized process. Self-review
and a large test count cannot establish conference suitability.

Choose one framing: a specific useful systems finding with supporting
assurance; a substantive mechanized security/refinement result beyond routine
composition; or a rigorous prior-separated negative result. If none survives,
retain and deliver company engineering without relabelling it as a new
cryptographic primitive. Venue selection follows the result.
