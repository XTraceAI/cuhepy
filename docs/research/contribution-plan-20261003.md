## 1. Recommended direction and honest claim boundary

Develop a system that optimizes **evaluation and safe verification together**
for an owner-private, repeatedly queried index. The first creative question is
whether selective index preparation can move expensive secret-dependent digit
boundaries out of the online proof while preserving a favorable complete
memory, preparation, update and noise frontier. A second, independent question
is whether a certified decoder-event algorithm can bound the actual dependent
noise graph without enumerating its full state. A TEE/proof partition is an
enabling comparison route. A one-limb exact-HE feasibility screen is a small
orthogonal alternative, not a commitment to BFV or BGV.

There is **no selected original main construction yet**. In particular:

- Shared binary/odd-ring proof oracles now have a direct BitZ control. Porting
  that method to our frontend is useful integration, not our new PCS.
- Nondeterministic bounded decompositions and semantic correct release have
  direct prior work. A new exact-score application is not automatically a
  new safe-release theorem.
- The functional-key identity below is an external-product/preprocessing
  control. Its possible contribution is a specific new complete graph/frontier
  algorithm or demonstrable tradeoff, not inventing gadget ciphertexts.
- Native/CUDA/RNS improvements remain company results. Conference acceptance
  cannot be promised by this plan or by a count reduction.

The project should pursue a paper only after one precise uncontained algorithm
or restricted theorem survives the strongest controls and has a useful measured
consequence. If all candidates stop, retain the system and publish accurate
engineering/negative findings where appropriate; do not manufacture novelty.

## 2. Contract, deployment and system boundary

The owner/client owns the index and queries and may retain **all plaintext**.
The default research contract is one malicious compute server, owner-approved
registration and epochs, adaptive private queries, all exact distances with
stable record IDs, and observable accept/abort. Local stable top-three follows.
Exact-top-three-only, approximate search, noncolluding helpers and plaintext
inside a TEE are separate modes, with separate leakage and trust statements.
The [existing exact contract](exact-search-contract.md) remains authoritative.

Preserve the homemade HE implementation and native public evaluator as the
company baseline. Keep external proof backends and SEAL as labeled controls.
Experiments stay under `experiments/bfv_search_lab`, with independent oracles,
`benchmarks` runners, raw receipts and research reports. Integrate into package
crypto/client APIs only after correctness, usefulness and security gates; no
production branch or fallback needs modification for the research screens.

The proposed architecture has five explicit boundaries:

1. **Owner enrollment:** encrypt/compile the index, prepare permitted auxiliary
   keys, authenticate the graph/parameters/IDs/epoch, and price all work/state.
2. **Original query:** generate fresh private coins, encode canonical bytes,
   derive public query digits locally where applicable, and bind the request.
3. **Untrusted evaluation:** run the selected homemade CPU/CUDA graph and
   produce the complete proof/receipt for the declared output relation.
4. **Public admission:** authenticate the owner-approved instance, check the
   original query, every required boundary and all response bytes before a
   long-lived HE secret is used. No server-chosen circuit or RHS is accepted.
5. **Private finish:** decode the admitted response with the matching exactness
   bound, recover IDs/ties, and maintain the declared lifetime/rollback state.

An enrollment digest does not by itself implement a low-state verifier. Current
Context validation traverses the whole index and keys. A future immutable
authenticated registration cache must specify update invalidation, compromise,
rollback and memory, and be available equally to all controls.

## 3. Track A: move and choose expensive native proof boundaries

**Hypothesis:** under fixed-index reuse, a mixed graph can trade some offline
gadget preparation for fewer online canonical source witnesses. The actionable
research target is a representation/scheduling algorithm that prices proof,
noise, public query work, key residency and updates together, and improves
against the best complete fixed representations.

### A1. Concrete first construction and exact cautions

For index ciphertext `A_i=(a0_i,a1_i)` and query `C=(c0,c1)`, with phase
`phase(A_i)=a0_i+a1_i*s`, the owner can prepare fresh keys

```
K_i,j = RawGadgetEnc_s(B^j * s * phase(A_i)).
Y_i   = c0 * A_i + sum_j digit_j(c1) * K_i,j.
```

Here `RawGadgetEnc_s(M)` has phase `M+t*E` in the full Q ring, as a gadget
evaluation key does. Ordinary plaintext `encrypt()` may reduce M modulo t and
is not a valid implementation of this key. The target includes the existing
index phase's error. The phase of `Y_i` is `phase(C)*phase(A_i)` plus the weighted fresh key errors.
Only the original public query component is decomposed for this product step;
the index-dependent product source no longer needs its own digit witness.
This algebra is known functional/gadget preprocessing. It is not a security
reduction: the correlated degree-two secret/data-dependent key messages need
an explicit key-dependent-message/evaluation-key premise and a matching proof.

Do **not** derive these keys by multiplying ordinary relinearization keys by
uniform `a1_i`: that also multiplies their errors by full-Q coefficients.
Do **not** replace a rotated index by an arbitrary fresh encryption and multiply
its error by uniform query coefficients. The favorable bound relies on the
stated cancellation. If both components need new encryption, bounded-decompose
both and compare against ordinary RGSW/GGSW external products.

The product-only variant leaves downstream rotation boundaries. With T tiles,
V rotation cuts and S=T+V original cuts, its count is `S'=1+V`, not constant.
For the existing layout's count model at N16,384/D512:

| Vectors | T | V | Ordinary cuts | Product-only cuts | Extra fresh product-key family |
| --- | ---: | ---: | ---: | ---: | --- |
| 8,192 | 256 | 511 | 767 | 512 | L4: 480 MiB packed Q120 or 512 MiB two-word RNS |
| 32,768 | 1,024 | 1,022 | 2,046 | 1,023 | L4: 1.875 GiB packed or 2 GiB two-word RNS |

These are deterministic layout/storage **models**, not native candidate
executions or gains. They replace one shared 1.875 MiB packed/2 MiB RNS relin
family with index-specific families; rotation keys, residency, transcripts and
workspaces remain paid. At the tiny E106 layout, cuts only fall10→6.

The strongest full control may precompile both query components and selected
automorphism orbits using GGSW/functional keys. Then original-query digits are
publicly reproducible, but the per-index/per-orbit preparation can be much larger.
Give that control identical owner setup, seed compression, hoisting, hardware
and graph fusion. A query-public affine graph alone is already established.

### A2. Proposed E110 discriminator before a compiler

1. Freeze a one-page difference card against Bae's matrix-RGSW/external-product
   methods, ordinary hoisted/functional switching, E07, E29 and E72. Specify
   owner roles, correlated-key distributions, rotations and proof statement.
2. Build a homemade tiny integer/phase oracle for ordinary, product-only and
   fully gadgetized/orbit controls. Use the frozen E106 queries, partial tiles,
   every limb, stable ties and full terminal bytes. Different valid graphs may
   produce different ciphertext bytes; compare exact plaintext functionality
   and bind each graph's own declared wire relation, not artificial byte equality.
3. Test actual fresh-error bounds, aliases, cross-limb digits, fresh-rotation
   noise amplification and key substitution. Reject unbounded noise shortcuts
   before native/CUDA implementation.
4. Emit a complete cost card: all keys/owner products/NTTs/digits/rotations,
   public verifier query work, proof/range inputs, setup, update, memory, lifetime
   and private finish. Initially use counts, not timing predictions.
5. Compare all-ordinary, all-gadget, product-only, feature-major and equally
   optimized mixed controls. Stop if a named existing algorithm provides the
   same graph and frontier, or an optimistic paid ledger is already dominated.

**Cap:** one prior/difference component, then one tiny oracle/count component.
If neither yields a precise uncontained step, stop E110. Do not build another
large optimizer merely because the identity is correct.

### A3. Conditional algorithm if A2 survives

Represent each legal materialization/rotation boundary by its ciphertext key
domain, coefficient support, degree, canonical source, available gadget basis,
exact noise envelope, proof-oracle support and authenticated enrollment state.
Explore selective preparation of a small shared orbit basis, versus compiling
every tile/orbit. Charge common query digit sources once only where the actual
graph permits it. Keep terminal conversion and common-integer consistency.

Prove transition correctness and completeness **within a stated finite grammar**
and compare an independent exhaustive Pareto oracle on tiny graphs. A weighted
min-cut or DP alone is standard; the possible new step must be a graph rewrite,
state sufficient for legal composition, or a theorem about the new cost frontier
that existing HE compilers do not already supply. E52/E63 show why rank and
simple byte totals can be insufficient state; E65/E57 show why stronger simple
controls can eliminate a supposed optimizer benefit.

Only after that gate, implement the best fixed/mixed graph in C++/RNS, then CUDA.
Prioritize new algorithm tests over routine kernel tuning. Measure real proof
costs and all registration/updates; use held-out workload and update sequences,
not the same traces used to select a layout.

## 4. Track B: certify the decoder event, not the full noise state

**Hypothesis:** a certified residue/carry decision tree can bound a complete
decoder failure event using less work than full fresh-error enumeration, without
assuming independent canonical digits or marginal noise terms.

E105's full source map is injective: all6,561 CBD1 states are distinct. Full-state
merging is stopped. However, injectivity does not forbid a smaller certificate
for whether the **decoder event** occurs. This is a different proposed algorithm,
not a claim that such compression exists.

### B1. Proposed E111 oracle and certificate

Freeze at most three disclosed tiny setup contexts and the complete actual
product/relin/rotation/terminal graph. Branch on exact fresh CBD atoms. Every
cell carries its exact probability mass and a conservative joint enclosure of
the same error vector through original phase, modular sources, canonical digits,
maintenance and final decoding. Split at relevant residue/carry boundaries where
possible. Do not replace joint `(P(E),R(E))` by products of marginal laws.

A leaf may certify every completion safe, certify every completion unsafe, or
remain unresolved. Use outward integer/rational bounds. The sum of certified
unsafe plus unresolved mass is an upper bound on failure. Preserve a lower
bound from certified unsafe mass. Return the interval and an independently
checkable certificate; never silently discard unresolved mass.

Test against exhaustive weighted CBD coins and the actual API on tiny cases,
including E105's covariance/tail counterexample and adversarial carry-boundary
queries. Require identical full-event truth with every certificate claim.
Compare optimized generic weighted branch-and-bound, exact convolution where
valid, deterministic support bounds and the strongest applicable finite-MGF/
dependent-noise methods. Give them the same linear normalization/caching.

Record cells, exact masses, enclosure width, unresolved mass, certificate bytes,
generation/check operations and memory. The new method must reduce work at the
same certified probability interval; merely widening the interval is not a win.
Full-Q masks can make a ±1 error change cross many digit boundaries, so no
rare-carry/locality assumption is available.

**Stop:** certificate/frontier cost reaches exhaustive/generic control at the
same certified probability interval; useful bounds are no tighter than the
matched deterministic control; or the method is already a known certified tail
algorithm without a new consequence. Cap one symbolic rule and one tiny panel.
Exhaustive certification of zero failures proves probability0 for that fixed
conditional finite experiment. Otherwise the16-bit coin support has minimum
nonzero mass2^-16. Neither observation nor that restricted exact-zero result
establishes a2^-128 production/setup/adaptive-lifetime bound.
Projected-map injectivity alone is not a stop: an injective map can still admit
a compact certificate for its decoder event. It only rules out literal state
deduplication.

### B2. Conditional finite-lifetime theorem

If B1 survives, prove certificate soundness by induction on cells, then separate:

- one bad-setup event for the reused secret/index/evaluation-key distributions;
- a fresh-query conditional failure term uniform over the declared legal query
  set and history, under explicitly stated randomness/conditioning premises;
- every publicly admitted malicious witness, if a semantic relation is used;
- terminal switching/decoder margin, total attempts, updates and retry leakage.

Declare certificate visibility before a real-setup extension: owner-local
analysis, a public parameter-wide certificate, and a published per-private-setup
or per-query tree are different interfaces. Publishing an exact tree specialized
to secret/key errors or fresh query coins may disclose those values. Require a
no-secret-disclosure statement or a separately paid hiding/zero-knowledge
mechanism; disclosed toy certificates do not authorize such production release.

Do not condition fresh coins on public transcripts as if information-theoretic
independence followed from computational encryption. If uniformity over adaptive
queries cannot be proved, retain a fixed-query or honest-evaluator theorem with
that restricted scope. Deterministic adversarial-digit bounds are a control.
The research result must be the new certified algorithm/bound for the actual
reuse graph, not a union bound already supplied by E102's standard adapter.

Only a reviewed bound that changes a **complete** parameter/body/level frontier
justifies a production-sized implementation experiment. Lattice hardness,
sample laws and reduction losses remain separate. No Q reduction is approved
here.

## 5. Track C: a TEE verifies only the authentic proof boundary

**Hypothesis:** a protected checker can validate the exact integer/range tape
consumed by an untrusted affine proof with less trusted work than full native
replay. This is an enabling systems/composition route; HE-plus-TEE and Freivalds
alone are established by Slalom and related work.

### C1. Proposed E112 protocol/cost discriminator

Write a message sequence and security invariant before implementing a service.
The owner enrolls approved code, graph, parameters, index/key digest, epoch and
release domain. The TEE receives the actual canonical tape/oracle opening data,
checks common-integer/RNS linkage and every required terminal boundary, and
authenticates **the exact commitment and statement used by the affine proof**.
It must reconstruct/check the complete required tape commitment, or use a
separately sound all-coordinate range/common-lift argument. Sampled PCS openings
alone do not establish that every nonlinear boundary is valid.
The client validates attestation and the proof/receipt before secret use.

A signed digest of a different tape is insufficient. Reuse E106 false canonical
kernels, commitment substitution, mixed original queries, signed malformed
digits, unused coefficients, epoch replay and rollback. State whether the TEE
holds HE secrets or plaintext; the first sketch should need neither. Price
witness upload, trusted parsing, commitment/oracle construction, memory, PCS
work, attestation, transcript storage, invalidation and total attempts.

Compare full CPU replay, complete cryptographic proof, an equally optimized
Slalom-style checker, ordinary hybrid partitioning and approved plaintext TEE
execution as distinct trust modes. BitZ/ring methods receive their best ranges.
Stop if authenticating the actual oracle costs as much as trusted replay or
if partitioning does not beat the strongest hybrid control.

**Cap:** one complete protocol/composition card and one paid cost ledger first.
A local simulated signer is only a test control. A later AWS Nitro experiment
must use real attestation and durable lifecycle. NVIDIA confidential-GPU
attestation is a future hardware-specific alternative; the current RTX3080
benchmark GPU supplies no such assurance. Do not treat a Nitro CPU receipt as
authentication of unchecked GPU output.

## 9. Reduction and security agenda

The final paper should prove a composition that matches its implementation,
not just cite IND-CPA for the underlying encryption. Draft separate obligations:

1. **Enrollment binding:** authenticated owner graph/index/key/ID/epoch and
   immutable instance handling; malicious enrollment is a separate extension.
2. **Arithmetic exactness:** relation satisfaction implies declared exact scores
   and stable coverage/ties, including RNS common integers, bounded digits,
   terminal rounding and every admitted semantic alternative.
3. **Proof/receipt soundness:** all openings/challenges/commitments, scalar/ring
   domains, extraction where needed, replay and total lifetime attempts.
4. **Feedback simulation:** verification and correctness/rejection observations
   must be simulatable under the actual adversary. Fherret/vCCA/vFHE/Phalanx
   define stronger controls than checking honest ciphertext equality alone.
5. **Privacy:** adaptive index/query encryption, seeded randomness and extra
   correlated functional keys under explicitly stated assumptions. No generic
   IND-CPA citation proves degree-two KDM or malicious-response security.
6. **Finite reliability:** actual setup/fresh-error dependencies and admitted
   witness bounds; exact distributions, decoder tails and lifetime losses.
7. **Trusted lifecycle and implementation:** real attestation, protected state,
   rollback/revocation, concurrency/crash behavior, parsing/resource admission
   and private side channels. Constant-work diagnostics are not a complete
   constant-time proof.

An illustrative failure-budget decomposition must list proof/commitment error,
bad setup, per-query correctness, transcript/hash/attestation assumptions and
lifetime factors. Do not add heuristic lattice cost estimates to statistical
soundness terms or infer security from tests. Seek independent cryptographic
and parameter review before claiming production readiness.

## 10. Research output and handoff discipline

The strongest possible paper story is conditional: **a new complete boundary/
representation algorithm or certified dependent-noise method, a matching
restricted theorem, and an end-to-end system demonstrating its resource
frontier**. Exact encrypted Hamming search supplies the application and stable
ties; it is not the novelty by itself. Generic reusable safe release and novel
PCS claims remain off the table unless the closest-work gap is actually proved.

For every component, record hypothesis, exact prior difference, frozen source/
fixture, result type (measurement/count/theorem/control/negative), all costs,
passed/stopped/unknown status, and the next packet. Keep test counts scoped.
Update the canonical plan/queue and progress, preserve old receipts, then return
to the earliest unmet gate. Archive exact paper revisions and rendered reading
scopes; do not equate a downloaded paper with an audited proof or reproduced
benchmark. Venue selection follows the result. CSF/FHE conference preferences
do not justify weakening the contract, baselines or claim standards.
