# Q32 / E106: complete native boundary before the next mechanism claim

2026-10-03 UTC. Proposed, **not implemented or measured**. This is the next
prerequisite after the [E101–E105 return](boundary-reuse-selection-20261003.md),
not an accepted original construction. Keep the [primary contract](exact-search-contract.md),
owner plaintext caches and all existing homemade backends. Do not restart
the contained canonical-cut or carry recipes under a new name.

## Why this is the next useful work

E101 closed a real packed-query BGV reference relation and a separate tiny
no-rotation RNS relation. It did not close the actual rotated native graph,
terminal codec, or BFV's integer scale-and-round. E105 closed the registered
fresh-error domain for one supported structured setup; it did not prove a
general honest-key maintenance tail. A cost or security conclusion across
these missing boundaries would be premature.

Build one complete, strong **known-control adapter**, then identify whether
its actual bottleneck leaves room for a distinct representation. Its value is
to make the next research question testable, not to establish novelty by
implementing a verifier. Missing comparison costs stay unknown. No new timing
panel, CUDA kernel, parameter reduction or production promotion precedes this
return.

## Second bounded component: independently close the chosen boundary

Write a homemade integer/RNS oracle from original pinned ciphertext bytes to
the exact response bytes and decoder dependencies. Compare it with the actual
backend on a declared tiny supported fixture. Cover full coefficient phases,
all returned distances, stable IDs and ties, partial tiles, padding and the
enabled terminal format. A modular product identity does not by itself
enforce canonical digits, CRT lifting, integer range or half-tie rounding.

Mutation checks must include one corrupted RNS limb, each nonlinear source,
nearest reachable terminal rounding boundaries, dropped/duplicated/reordered rows, substituted
original query, epoch/key/layout mismatch, and **honest final output with a
false intermediate witness**. Bind the exact complete accepted statement.
Specify failure observations before HE secret use; private timing and durable
anti-rollback remain separate implementation obligations. An affine residual
test alone is not a complete proof of the nonlinear statement.

Check whether exact half ties are reachable in the selected arithmetic rather
than manufacturing them. For example, with odd Q, the integer nearest-rounding
tie equation `2*P*c=Q*(2*k+1)` has an even left side and odd right side. Record
that unreachability and test the closest legal coefficients on both sides;
document generic helper tie conventions separately.

## Strong controls and the decision this must enable

Price the same complete statement for:

1. Full native recomputation and an attested full evaluator.
2. The fused E13 product/relinearization control extended to the chosen
   rotation/terminal path, and E72's once-compiled fixed-index adjoints.
3. Equally optimized generic canonical-cut elimination, including common
   subexpressions, grouped public operators and all supplied or derived digits.
4. The applicable specialized ring/double-CRT verifier, under its actual
   field, range, proof-system and preprocessing premises. Retain explicit
   mismatches if a complete adaptation is unavailable; an algebra/count model
   is not an author-artifact performance reproduction.

Use the [closest-work audit](closest-work-roadmap-refresh-20261002.md#3-closest-complete-mechanisms-for-verification)
and pinned archive for Slalom, lattice-SNARK vFHE, ring public vFHE and
small-prime proof controls. Generic Freivalds, a PRG seed, geometric weights,
polynomial identities and ordinary lookup reuse do not establish a new result.
All receive the same fusion and native arithmetic where their contracts permit.

Separate owner registration, server witness generation, protected checker,
client release, every network link, hints/challenges, dense private state,
CRT/decomposition work and lifecycle costs. Show actual RNS words versus
hypothetical packed bodies. No plaintext/HE secret is supplied to the no-key
checker. A checker compromise can forge release and recreate the feedback
oracle; it is not covered by an unconditional privacy assertion.
