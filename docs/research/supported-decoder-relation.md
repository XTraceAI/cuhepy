# P07/P02 supported-coordinate relation (E62–E64)

2026-09-30. This specifies a separate research profile before extending E62.
It is an algebraic correctness argument and a conditional integrity argument,
not a reviewed privacy theorem, parameter approval or communication lower
bound. The [direct-fresh draft](direct-fresh-conditional-security.md) lists
additional encryption, mask, setup, lifetime and private-timing obligations.

## Fixed owner-approved inputs

The owner pins full encryption N, prime Q, plaintext prime t, key, random
index epoch, exact public query space, decoder/layout, row order and stable
IDs, and the private representation identity. This approval remains local;
an unsalted digest of private maps/rows is not a public commitment. Online
queries consume fresh original masks. All epochs share the declared global
verification-attempt allowance. Representation migration, rollback, malicious
preprocessing and durability are outside this fixed-epoch profile.

For R replies, let D_t be the linear map over F_t from R full phase polynomials
to every enrolled score coordinate, including CRT reduction, inverse padding
and row restoration. The private affine anchor is added afterwards. Define
K_r as the coordinates whose column in D_t is nonzero. The E63 certificate
computes exactly these sets for supported dyadic CRT/score layouts, and its
independent matrix oracle evaluates every unit input through the actual
decoder on tiny instances. No sparsity property of the secret key is assumed.

The honest public evaluator is C*(request) = answer + sum_j A_j times the
actual centered-lift correction_j in F_Q[X]/(X^N+1). Its original deterministic
phase certificate is retained. The checked relation is

```
P_K(C) = (C0_r[K_r], C1_r[0:N]) for each reply r,
P_K(received) = P_K(C*(pinned request)), with exact owner-derived bounds.
```

Every C1 coefficient is included. The server cannot name new supports,
substitute another layout/epoch, or omit additional coordinates. Packet shape,
order, coefficient range and unused encoding bits are canonical. Index and
offline answer fingerprints are generated by the owner, never by the server.
This projection concerns the returned relation: full index components and
all correction shifts still participate in owner preprocessing and evaluation.

## Correctness of omission and dedicated decoding

Let Z_K keep K_r and zero other phase coordinates. By the definition of K,
each omitted decoder column is zero, hence D_t Z_K = D_t on **all** F_t phase
vectors. This identity is independent of the index rows and query. It is also
necessary for this fixed coordinate-deletion model: if a column is nonzero,
the zero input and that unit input agree at all other coordinates and decode
differently. This is not minimality against other encodings, public C1 recipes,
extra preprocessing, switching, client-local scores or a changed output.

After relation acceptance, compute full C1_r*S in the original full-Q ring.
For i in K_r only, center (received C0_ri + (C1_r*S)_i) mod Q using the original
convention, assert the owner-derived honest phase bound, and reduce mod t.
Put these verified field values in a **field-decoder carrier**, with zero at
other positions; apply the approved D_t. This carrier is not a ciphertext and
must never be passed to ordinary BGV decryption. A zero-filled C0 ciphertext
need not satisfy a bound at omitted coordinates.

On exact relation acceptance the selected phases equal the honest phases;
the omission identity proves every score, ID and tie is unchanged. A zero
score count needs no decryption, but the complete base relation can still be
checked before applying private deletions/insertions. Existing private overlays
operate after exact base results and introduce no extra server-controlled
input to secret-key arithmetic.

Reducing supplied C0 modulo t is unsafe: centered-Q reduction does not commute
with that operation. E62 retains an explicit Q=257, t=17 carry counterexample.
Deleting C1 is likewise unsupported: negacyclic convolution lets every C1
position influence a selected phase for a legal ternary basis secret. This
structural witness is not a statement about all secret distributions or a
general compressed-ciphertext lower bound.

## Conditional gate argument and limits

Use c independent ideal uniform hidden F_Q vectors on exactly P_K's
coordinates. The owner prepares the corresponding adjoint fingerprints of
the full trusted encrypted index and honest offline answers. Linearity holds
over F_Q for the *actual centered correction lifts*, including their shifts;
it does not require those lifts to be linear over the plaintext field.

A fixed wrong projected relation has a nonzero error vector, so one challenge
collides with probability 1/Q and c challenges with probability 1/Q^c. For an
adaptive bounded verification-only transcript, couple to an oracle that rejects
every wrong relation. Until the first false acceptance, accepted correct
relations and rejected wrong relations expose no challenge-dependent outcome;
the all-reject path determines each attempted error independently of the
hidden challenge vectors. A union bound gives B/Q^c for the first false
acceptance. Do not assert a fresh 1/Q^c conditional probability after each
observed rejection; the [lifetime oracle](exact-search-security-game.md) tests
that distinction. For multiple fields/epochs use the actual sum of allowances;
refreshing a checker does not refresh the global declared lifetime budget.

The implementation replaces ideal vectors with private SHAKE seeds, requiring
the corresponding PRG hybrid. It inherits exact field/phase checks and one-use
registration from EpochCheck. Parsing/rejection uses no HE secret. This does
not supply side-channel assurance, authenticated provisioning, durable
anti-rollback, multi-process accounting, a proof for related seeded encryption,
or privacy under secret-bearing timing observations. A complete projected
protocol must reconcile these obligations and its changed ideal functionality
with the direct-fresh draft before deployment. Full-response verification
remains an independent reference/fallback.

Known ingredients include linear decoder support, [GLWE sample extraction](https://www.zama.org/post/tfhe-deep-dive-part-4),
CRT algebra and secret linear checking. Any originality must survive a closest
work review of the joint optimization domain and algorithm; this argument alone
does not establish it.
