## The next implementation sequence

1. **Authoritative enrollment and shared preparation.** Compile the owner
   relation internally from copied original index, keys, parameters, ordered
   IDs and one fixed plan. Freeze the original query in a request context.
   Reject unsafe public bounds before producing a usable context. Remove the
   small Python schoolbook coefficient-preparation bottleneck by compiling
   public recipes into shared two-prime NTT tables, with a factorized or
   streamed alternative where appropriate. Intern repeated roots and
   automorphism maps. Report native owned bytes, scratch, setup work and
   invalidation dependencies; do not infer them from multiplier-table bodies.
   The caller must not select an arbitrary graph, key column or lift.
2. **One protected admission controller.** Bind the exact snapshot, epoch,
   ordered IDs, query, profile, primes and their order, key set, plan, source
   coverage and terminal contract in a canonical request/response grammar.
   Validate the whole immutable packet before relation arithmetic. Call the
   complete native equality kernel and construct the authoritative congruent
   nearest-lift compact frame from its verified full-Q outputs. Compare the
   complete claimed frame, including unused coordinates, before exposing any
   release hook. Own request state and process lifetime internally; prevent
   copying, replay, concurrent release and stale snapshot use. Define durable
   restart/update behavior explicitly rather than treating a local lock as a
   deployment guarantee. Start with a public controller and a recording hook;
   private decode and attestation are separate reviewed integrations.
3. **Matched native source producer.** Extend an isolated homemade evaluator
   to emit exactly the enrolled retained sources and complete terminal-Q
   components for canonical30 and no-seed30. Extract canonical common-Q
   integers from the actual ordered limbs, not independently supplied limb
   digits. Serialize fixed slots directly, and count source inverse NTT/CRT,
   query processing, allocations, tape extraction and bytes. The server must
   never prepare an expected response for the verifier as a substitute for
   its independent relation check. Preserve delivered CPU/CUDA libraries.
4. **Complete correctness and lifetime gate.** Register the source closure,
   inputs, binary/build receipts and acceptance cases before fresh keys.
   Start with the existing small geometries and actual two-prime keys, then
   one source-profile correctness cohort. Compare whole residual vectors to
   the independent schoolbook oracle and whole terminal frames to the exact
   rounding oracle. Compare plaintext coordinates, distances, stable IDs and
   top-k only as diagnostics after public admission. Test substituted query,
   index, key, plan, IDs, epoch, coverage, source ranges, malformed last block,
   independent-limb forgeries and altered unused frame coordinates. Include
   replay, concurrency, fork, stale contexts, enrollment failure and no release
   after any rejection. HE replay and private APIs must be unavailable in the
   checker regression. Preserve failed starts and scope retries separately.
5. **Return to Q72 only after that gate.** Register one fixed source profile:
   N=16,384, D=512, the original Q/P/t/eta contract, 8,192 and 8,224 vectors,
   and one 16,384-vector no-saving control. Use a small declared held-out query
   count, one backend and matched reuse. Measure producer, extraction,
   serialization/transport, verifier, trusted terminal, client and elapsed
   critical path. Charge setup, selected keys, native peak memory, updates and
   amortization. Compare canonical admission, equally rewritten prepared
   replay, the historical checked-product/trusted-suffix contract and permitted
   plaintext caching. Retain trust/output differences in the result table.
   Run CPU first; a CUDA port requires a surviving complete bottleneck and a
   declared useful frontier. Retain contention/resource failures explicitly.

Each numbered component needs a dated registration, complete evidence receipt
and ledger return. Completion advances to the next component; an explicit
failed prerequisite stops dependent timing or backend work. No unrestricted
radix, optimizer, dataset or timing grid is authorized by this plan.

## What would make this a worthwhile original systems result?

The hypothesis is a **noise-safe change to the evaluated relation that changes
the paid verification frontier**. Public gadget propagation, composite keys,
Karatsuba, DP, compiler fusion, streaming and exact NTT equality are established
controls. The strongest compatible control gets the same equations and rewrite
opportunities. The retained closest-work registry and primary-source comparison
must separate any claimed system distinction; missing an identical application
name does not establish priority.

Q73 has three possible returns after the complete measurements:

- Select a full system if the complete assurance contract and a reproducible
  useful setup/state/update/online frontier survive equally specialized controls.
  State the precise prior-separated mechanism and which deployment actually
  benefits. Develop the reduction/coupling argument for that concrete contract.
- Keep a supporting or negative result if the algebra is correct but paid
  replay/cache/fusion removes the useful distinction. Preserve the engineering
  and do not promote a stage-only saving to a paper's main result.
- Investigate one new mechanism only if the measurements isolate a precise
  unresolved cost or assurance barrier, with an independent closest-work check
  and a bounded discriminator. Do not reopen H1/H2 or E101/E110 under a new name.

The current small native components use no SEAL and no secret operation. They
establish neither source-profile parameter assurance, private side-channel
protection, attestation, production authorization nor a publication-ready
novelty claim. Those obligations stay explicit while the next build proceeds.
