## Completed relation

The independent trace implements integer negacyclic products, automorphisms,
signed monomials, canonical unsigned gadgets, key switching, every expansion
branch, all three product components and the owner-derived terminal projection.
It calls neither the existing expansion nor multiplication for its arithmetic.
Its typed DAG binds approved encrypted index, keys, epoch/ID/projection context,
full-Q/RNS interface, original C0/C1 and accepted output. Public binding hashes
contain encrypted/public objects, never plaintext index digests/private hints.

All **112 encrypted searches** agree coefficient-for-coefficient with E73's
canonical expansion and existing evaluator. **336 switch witnesses / 86,016
digit coefficients** are checked; every score, stable ID and top-3 is exact.
Scoped tests: **54 passed** (26 E78,28 existing E73/E77); three Ruff paths pass.
Controls corrupt original C0/C1, seed/token/epoch, index/key/context, branches,
digits/ranges/switch outputs, expanded inputs, C1/C2 and projection. A true
output with a corrupted witness fails the relation. No inner-key call occurs
in the checker. An x+Q witness passing modular recomposition fails canonical
integer recomposition; this rejects a canonical-relation shortcut, not every
bounded noncanonical protocol.

**This checker recomputes the public trace.** It is not a cryptographic proof,
commitment, small verifier or a production release boundary. No mock PCS or
hash is substituted for cryptographic binding/extraction. Private timing,
durable lifetime, parameter and adaptive privacy assurance remain open.

## Factoring and complete three-design comparison

At fixed C1 every C1 branch and gadget is independent of C0:

```
E_j(C0,C1) = (S_j*C0,0) + delta_j(C1)
Y = A_D*C0 + b_D(C1).
```

This holds for the complete ciphertext relation, not only decoded scores.
The C0 intermediate branches can be folded; key-B contributions can be folded
through fixed index multiplication/projection. But subsequent gadgets depend
on key-A/C1 branch recurrence. That seed circuit still needs all original-input,
canonical integer/range and modular product relations. A strong separate-proof
control receives the **same** generic linear folding/batching; no strawman
commits every temporary NTT vector. Closest maintenance/ring/batched proofs
already support these transformations.

The raw compares three explicit interfaces:

1. Canonical expansion plus multiplication proof, with optimized linear folding.
2. Composed original-to-output proof, eliminating the expanded-query *interface*,
   while retaining the same necessary seed gadgets. Proof/backend costs remain
   unknown, not zero; removed materialization is not proof of faster proving.
3. Certified seed offset plus affine gate. A public certificate does not give
   private beta. Sending the full certified b costs another accepted-output-sized
   body and its proof/check work; a committed b needs a specified private-query
   opening, or the old paid trusted factory. Neither interface is supplied free.

An additional circuit-transposition idea fingerprints C1 and every independent
gadget polynomial directly. Its private coefficient count is
`rounds*N*(1+(H-1)*ell)`, versus E77's `rounds*2*columns*N`. On toys H4/ell8
it is **3.125x** the expanded fingerprints. On all eight retained profiles it
is **8.73–13.95x**, before the compiled C0 vector and checking challenges. This
rejects that literal state representation, not every compressed secret opening.

The selected Mushroom/Semeion legacy models each have **9,142,272 canonical
digit coefficients** (36,569,088 digit-range bits in the simple bit inventory).
Both composed and strong separate controls retain them. Those are symbolic
witness/range counts, not measured proof time or a lower bound on any proof
system. Global RNS reconciliation/quotients/carries are explicitly required
if the backend does not operate in the matching full-Q ring. Keys, index,
original seeded/unseeded request, all output components, private state/beta
and setup bindings are listed. Actual PCS commitment/opening/proof bytes and
prover/verifier costs remain unresolved. No full-cost win can be inferred.
