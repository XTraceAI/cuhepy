## What the screens changed

1. The central question is still **trusted preparation + safe compact release**.
   Simple output packing, generic triples and another optimizer do not supply
   a new mechanism. Implicit convolution structure survives linear registration
   operations but not a naive universal gadget-limb factorization.
2. An actual encrypted-query reference now exists in
   `experiments/bfv_search_lab/encrypted_query_certificate.py`. It removes
   encrypted owner answers, so this functionality is no longer hypothetical.
   Literal query/proof/ticket costs are poor. Preserve the reference rather
   than claim a useful system or accelerate it.
3. A mathematical wrong-output bound is insufficient for reused hidden-state
   feedback. The correct-output/bad-quotient case can probe just one round.
   Fresh one-use hints avoid that particular reuse in E71 but must be charged.
   A new protocol must address this interface explicitly.
4. Measured authorized-cache acquisition and strong direct-fresh controls are
   now executable. A remote useful-resource frontier is still unestablished.

## A plausible contribution, still conditional

The most promising question is whether a **restricted structured ciphertext
operator plus a precisely typed release relation** admits a substantially
cheaper owner-bound certificate or admissible outer construction than generic
full-output verification. The point of invention would be the construction
and its complete resource bound, not polynomial identity testing, the NTT,
an adjoint identity, sample extraction, standard query packing or CUDA.

A candidate paper needs exact functionality, an adaptive-observable-failure
security statement, justified parameters and a useful measured resource regime.
Fresh randomness, seed/key provenance, authenticated enrollment and lifetime
state must match the reduction. Private timing/durability require their own
implementation assurance. Do not claim that finite-field regressions prove
IND-CPA, malicious privacy or reusable-checker security.
