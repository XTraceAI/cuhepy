# SB02: complete checked BGV reference admission

2026-10-03. **One complete tiny public reference path now works.** The controller
checks all producer product/relinearization tiles, computes the exact trusted
butterfly and terminal suffix, and releases only its own authoritative final
bytes. The result closes the selected partial-stage composition gap as a known
control. It establishes no actual GPU/enclave deployment, measured performance,
private-client release assurance, original main mechanism or cryptographic reduction.

Read the frozen [design](system-selection-gpu-admission-plan-20261003.md) and return
to the [bounded system-selection plan](system-selection-plan-20261003.md) after this
component. The design's earlier no-test scope is historical; this new report records
the separately approved reference implementation and one scientific cohort.

## 1. What was built and what admission actually checks

The new homemade [controller](../../experiments/bfv_search_lab/complete_checked_bgv.py)
reuses the existing E13 Python/GMP local-c2 product checker and supplies a separate
complete trusted continuation. No SEAL, native evaluator, GPU or proof backend is
called by this cohort. The owner-trusted public context is the unchanged disclosed
E106 N8/D4/dimension3/count9 profile. The new controller admits only that fixed
tiny geometry; it is not a production authentication API.

The five ordered encrypted index tiles are covered by three fixed blocks:
`[0,2), [2,4), [4,5)`. The block schedule differs from the trace groups4/1, so correct
block admission alone does not accidentally substitute for correct trace grouping.
The original query, complete source context/epoch, ordered index, key and global
positions bind every stage request. All block grammar, canonical residues and any
claimed complete response grammar are checked before the first fresh weight.

The existing product check computes c2 and its common full-Q canonical digits
inside the checker, then uses three fresh whole-polynomial checks in each prime.
It does not admit server-supplied digit strings or a host acceptance flag. Only
checked unshifted products enter the trusted continuation. That continuation
applies X^(1-D), the full butterfly and both rotations for the one-tile tail,
canonical rotation-key digits, nearest-congruent terminal conversion and all final
packet bytes, including unused coordinates.

If the producer also claims a final packet, it must equal the complete authoritative
packet. A public release sentinel sees only the locally computed bytes after every
check. This directly avoids signing/accepting a host-supplied final result without
establishing its computation. The reference contains no signature, Nitro verifier,
private decoder or unauthenticated fallback. A deployment must separately connect
this complete computation to an actual protected enrollment/receipt protocol.

The admission decision calls no expected-output replay or archived native hash
check. Those are external comparators in the
[runner](../../benchmarks/complete_checked_bgv_lab.py) and
[tests](../../experiments/bfv_search_lab/test_complete_checked_bgv.py).

## 3. Conditional guarantee and remaining security work

For a fixed immutable wrong product block in at least one native prime, fresh
uniform batch rows miss a nonzero residual matrix with probability at most1/p
per repetition. Three independent rows give at most1/p^3. An honest limb does not
multiply the corrupted limb's bound. Fresh post-snapshot challenges provide this
conditional bound under prior interactions. With globally counted attempted block
checks J, the ordinary unconditional union control is
`J/min(p0,p1)^3`.

Conditioned on trusted enrollment, no false block admission and correct trusted
continuation, deterministic canonical graph induction fixes all final response
bytes. This is the selected complete output-authenticity invariant, not an HE
security estimate or proof that arbitrary accepted masks always decode correctly.

The prototype consumes parent/block attempts before validation, refuses copy/
serialization/fork reuse and enforces bounded local parent state. New process or
enrollment instances can reset that nondurable state. Durable global owner epochs,
rollback/concurrency accounting, actual entropy and attestation/signature models,
HE parameter/noise assurance, source provenance, private-side-channel analysis and
malicious-server feedback reduction remain open. No production lifetime J or
security-bit claim is assigned by this result.

## 4. Paid system consequence and return decision

The reference proves feasibility of this complete known-control boundary; it is
not a performance experiment. The large N16384/D512/count8192 geometry would have
256 tiles and an uncompressed direct-RNS product output body of128MiB before
headers/protected transport. Its one-group25-bit compact coefficient body would
be102400B before framing. These are existing schedule/encoding geometry formulas,
not measured messages or a parameter/backend activation.

That same partial256-tile trace still executes `256+128+...+1 =511` trusted
rotations. Moving only initial products to the GPU therefore leaves substantial
trusted suffix work. A matched complete native replay comparison must charge all
product checks, trusted rotations/CRT/terminal packing, resident/prepared index/key
state, internal protected-boundary traffic, setup/update rebuilding, concurrency,
client work and actual receipt/attestation costs. Ordinary host copying is not
Nitro/vsock throughput. An unchecked full-GPU latency is not a safe-release result.

The [system-selection plan](system-selection-plan-20261003.md) should next use its
matched control/provenance work to decide whether a native implementation of this
boundary has a plausible useful frontier. Full native replay, equally specialized
Slalom/protected affine checking, applicable complete proof admission, permitted
plaintext caching and plaintext search in a protected service remain strong controls.
The existing design has broad prior containment; complete integration alone is not
an original paper contribution.

If measured trusted suffix work rules out product-only delegation, a separately
bounded design comparison may consider fresh layerwise checks of rotation/key
switches, with every tensor independently derived from the previous checked state
and exact full-output binding. That uses known randomized delegation too, and must
pay all layer output transport and trusted canonical conversion. It is a proposed
control alternative, not an executed successor or originality claim. No native,
GPU, scaled relation, new proof backend, larger scan or timing follows automatically
from SB02. **Return to R6: reference component complete; system/frontier and original
main selection remain open.**
