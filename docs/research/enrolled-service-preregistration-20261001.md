# E75 preregistration: matched enrolled TCP request control

Date: 2026-10-01. Return from R4/E74 to R2-C0. This is a control, not a new
protocol or an originality claim. Production code and historical runs stay intact.

## Finite task and premises

Run the existing homemade masked linear BGV/native full-Q checker and authorized
AES-GCM raw/zlib cache delivery through the **same bounded persistent TCP
request/reply harness**. Use the pinned Mushroom and Semeion fixtures, split3001,
complete enrollment rows/stable IDs, legacy N16384/selected t193 or t257/Q32
layouts, one warmup and three measured held-out queries per mode. The queries
are fixed, not an adaptive security test. Retain every exact score and stable
top-3 equality; diagnostic comparisons occur outside query timing.

Both endpoints start with their context and authorized private state. Actually
upload the seeded HE index and each independently encrypted fresh answer; the
server expands **received** packets and evaluates each **received** correction.
Time owner fresh preparation/hash registration, answer upload, request/reply,
client body parsing, the complete native check before any secret decryption,
decryption, score restoration and selection. A query's elapsed wall clock
contains the server and transport stages; do not add those nested measurements
again. The factory is the strong vectorized plaintext control, not the old
slow Python factory. Share the verification lifetime budget.

For cache modes, actually upload each sealed snapshot and download the received
stored bytes once, authenticate before parsing/decompression, and charge
acquisition and local queries. Compare raw, zlib1 and zlib9 delivery with raw
retention, plus zlib1/zlib9 compressed retention. Also measure the already
authorized owner's retained raw cache, with no acquisition. Cache compressed
length is declared leakage, so raw is the length-independent control.

## What this task cannot close

This is **enrolled endpoint / returning client** measurement, not full cold
deployment or enrolled-server/new-client provisioning. Private keys, HE maps,
IDs, fingerprints, context and cache keys/manifests are already pinned locally.
Report their canonical body models and actual setup time, but do not label the
models actual private bootstrap transfers. Same-process Python threads share
hardware and a GIL; this does not measure independent client/server CPU or peak
RSS. No WAN/TLS, GPU, durable replay/freshness, timing assurance, approved RLWE
parameters, full reaction privacy proof or service p95 is established. Socket
frames are measurement infrastructure, not a deployable authenticated protocol.

## Falsifiers and return to plan

Fail the run on any malformed packet acceptance, coefficient/score/ID mismatch,
gate bypass, reused answer, byte-count inconsistency or unsuccessful endpoint
shutdown. Retain per-query observations, framing and setup; never overwrite raw.
If HE is dominated by authorized caching in this finite regime, preserve that
negative and return to R3/R6. Do not accelerate a dominated mechanism or close
R2's still-unmeasured private bootstrap/independent-resource subcomponents.
